# DEFECT_LOG — SpendWise

This log records **real defects and incidents actually encountered** during
development of SpendWise, each verified against the codebase at the time it
happened. No speculative or planned-but-unobserved issues are listed.

| # | Phase | Defect / incident | Impact | Root cause | Resolution | Status |
| --- | --- | --- | --- | --- | --- | --- |
| D-01 | Batch source edits | A PowerShell-based bulk text update (`Get-Content` / `Set-Content` without an explicit encoding) risked corrupting UTF-8 file contents | Potential source corruption across edited Dart files | Windows PowerShell 5.1 defaults to legacy encodings | Verified every `lib/` and `test/` file byte-by-byte as UTF-8 and switched to UTF-8-safe tools (Python `pathlib` with explicit `encoding='utf-8'`, plus editor-based edits) | **Resolved — verified** |
| D-02 | Deprecation cleanup | A bulk Python regex replacing `withOpacity(x)` with `withValues(alpha: x)` over-matched nested call sites and inserted stray `)` characters | ~250 analyzer errors after the rewrite | Regex `[^(]`-sanity pass was insufficient for nested `Color XOR (...)` ternaries | All affected files restored from the previous Git commit (`c528be1`), the replacement re-run with a corrected safe pattern (`withOpacity\(([^()]+)\)`), and all remaining files individually verified. Post-incident rule adopted: no bulk regex refactors of code without a per-file diff check | **Resolved — restored + rewritten** |
| D-03 | Analyzer sweep | `flutter analyze` initially reported 250 issues (stray parentheses_corruption above, unused imports, misplaced `library;` directive, a `[..list]` typo where a spread `...list` was intended, deprecated `opacity` getters/`withOpacity` calls) | Build blocker | Combination of D-02 and normal drift | Fixed file by file; final scan (`flutter analyze`) reports **No issues found** | **Resolved — verified** (`flutter analyze` exit 0) |
| D-04 | Analyzer sweep | `lib/widgets/spending_chart.dart` still contained a deprecated `Color.opacity` ternary after the global rewrite | Analyzer warning | Ternary not covered by the safe regex pattern | Manually replaced with `barColor.withValues(alpha: 0.85)` | **Resolved — verified** |
| D-05 | Analytics correctness (test defect) | The provider test "monthly and today spending reflect the current month" used `yesterday = today - 1 day` for the "previous month" record. On the 1st–2nd of a month the test expectation itself becomes wrong (e.g. on 03 Nov 2026 the record falls inside the current month, so `monthlyExpense` = 390 not 140) | Wrong test data — not an app bug; the app's calendar-month slicing (`monthKey(date) == monthKey(now)`) was verified correct | Test fixture was date-dependent | Fixture changed to canonical previous-month dates (`DateTime(now.year, now.month - 1, 1)`), assertions unchanged (still expects 140). Suite is now identical on any calendar day | **Resolved — verified** |
| D-06 | Widget tests | `InMemoryStore` accepted a `seed` list in its constructor but never loaded it into the live record map; seeded dashboard tests saw zero records (`₹0`, `0 records`) | 5+ widget tests failed / gave false coverage | Constructor never invoked `reset()` | Fake now loads seed data in the constructor; all dashboard tests observe the seeded records | **Resolved — verified** |
| D-07 | Widget tests | Dashboard tests asserted on widgets below the default 800×600 test surface (`CustomScrollView` performs lazy building; the Save button of the tall form is beyond build extent) | False-failing tests, not an app defect | Test viewport smaller than the scrollable content | Test harness now uses a tall logical surface (800×1400) with `addTearDown` reset; no product code was weakened and lazy rendering is preserved | **Resolved — verified** |
| D-08 | Widget tests | "Non-numeric amount" test typed `12x3`, but the input formatter strips letters, so the field became valid `123` and the intended error could never appear | Test asserted on an unreachable state | Paste simulation fought the real input formatters | Test now simulates the junk that *can* survive sanitising (malformed decimal `1.2.3`); the app's `Amount must be numeric` path is genuinely exercised | **Resolved — verified** |
| D-09 | Form UX defect | Submitting with an empty payment method rendered the same error message **twice**: once from `_LabeledSection` and again from the `DropdownButtonFormField` validator | Duplicated error row; noisy UI | Equivalent validation wired at two levels in `add_expense_screen.dart` | Removed the redundant dropdown validator; the section-level message remains the single source | **Resolved — verified** |
| D-10 | Widget tests | Add/Edit flow tests pumped the screen as `MaterialApp(home: …)`; the success-path `Navigator.pop` popped the only route, leaving no Scaffold to host the success SnackBar | Impossible to assert success messages | Test topology differed from real usage (details screen shows beneath) | Tests now push the form above a host page, as the real app does; snackbars and the pop are both verified | **Resolved — verified** |
| D-11 | Launcher icon | `flutter_launcher_icons` was configured with `android: "launcher_icon"`, but the manifest references `@mipmap/ic_launcher` — the custom icon would not have been picked up | Launcher icon regression risk | Config/manifest name mismatch | Regenerated using the default name (`android: true`) so the generated `ic_launcher.xml` + mipmaps match the manifest reference | **Resolved — verified** |
| D-12 | Android resources | The `android/app/src/main/res` directory was accidentally deleted (`Remove-Item -Recurse`) during workspace cleanup | Splash theme, night styles, colours and all launcher mipmaps missing | Operator error (unsafe command) | Reconstructed from the standard Flutter template (`drawable/launch_background.xml`, `drawable-v21/`, `values/styles.xml`, `values-night/styles.xml`) and regenerated all generated resources (adaptive icon XML, colours.xml, all-densities mipmaps) via `flutter_launcher_icons`; full tree verified on disk and by release build | **Resolved — verified** |
| D-13 | Analyzer sweep | Remaining final analyzer issues after the restore: unused detail-screen import in the navigation shell, `SingleChildWidget` type reference after cleanup, spread typo `[.._expenses, …]`, misplaced `library;` directive | 4 analyzer errors | Drift from interrupted restore sequence in D-02 | Fixed individually; final `flutter analyze`: **No issues found** | **Resolved — verified** |
| D-14 | Release build | Every `flutter build apk --release` attempt failed mid-build with unrelated errors each time: `Unable to delete directory …/build/...`, Kotlin "could not close incremental caches / different roots", `AccessDeniedException` on `merged_native_libs` (each run after a JVM/daemon crash left stale locks) | Repeated blocked builds spanning several restarts | (a) Kotlin incremental caches cannot relativize paths across drive roots (pub cache on `D:`, project on `C:`), and (b) OneDrive file-sync locks files inside the workspace `build/` directory on Windows | `kotlin.incremental=false` in `android/gradle.properties` (with explanatory comment) + killed orphan Gradle daemons and paused OneDrive locally, purged the `build/` tree before the final build, then re-enabled OneDrive | **Resolved — release APK built successfully (50.9 MB)** |
| D-15 | Android config | `applicationId` was `com.spendwise.spendwise` (Flutter's default `--org` + project-name concatenation), while the approved configuration requires `com.spendwise` | App identity did not match the submission requirement | Template default | Set `applicationId = "com.spendwise"` in `android/app/build.gradle.kts`; the Kotlin `namespace`/package structure was left intact so `MainActivity` keeps resolving; final APK rebuild verified | **Resolved — verified/rebuilt** |
